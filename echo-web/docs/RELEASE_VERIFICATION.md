Branch: local `main` (baseline `f817306`, remote `origin/main` `50f1949` before this change).
Environment: Windows, Node 24, local FreeLLMAPI desktop gateway at `127.0.0.1:31415`, synthetic portal data only.

## Provider architecture - FreeLLMAPI primary

Provider priority in `server/services/echoConversation.ts`:

1. FreeLLMAPI when `FREELLMAPI_API_KEY` (or legacy `FREELMAPI_API_KEY` /
   `ECHO_MODEL_API_KEY`) is set.
2. OpenAI only when `OPENAI_API_KEY` is set **and**
   `ECHO_ALLOW_PAID_PROVIDER=true`.
3. Deterministic portal guidance when neither is available or the provider
   request fails.

FreeLLMAPI defaults: `FREELLMAPI_MODEL=auto:reliable`; development base URL
`http://127.0.0.1:31415/v1` when no base is supplied. Production requires an
explicit HTTPS base URL. URLs with credentials, query strings, non-loopback HTTP
or a path other than `/v1` are rejected. Keys never leave the server.

Each model-backed SSE response includes `event: meta` with `provider`, `model`
and the gateway's upstream route. `/api/echo/provider` (authenticated, no-store)
returns provider id, configured flag, model, base host, paid-provider flag,
last usage and a reachability probe. It never returns keys, prompts or replies.

## Security - 12/12 PASS

`tests/echo-security.test.ts` runs against the actual built-in router on an
ephemeral loopback port with no provider key or database. It verifies:

- anonymous session issuance is rejected (401);
- unapproved origins are rejected;
- no shipped/default secret can sign a usable token;
- malformed or non-numeric signed expiry is rejected;
- a valid token plus any suffix is rejected;
- unsupported body/tool fields are rejected;
- invalid signatures and expired tokens are rejected;
- reset revokes the token in-process;
- page context cannot carry a foreign URL or script;
- sessions are account-bound and rate limits/capacity bounds apply.

## Vercel status - NOT PROVIDER-CONNECTED

Before this change, the deployed site (`https://productivity-io.vercel.app`)
answered "Write only the word PLUMAGE. Use no other words." with the old generic
scripted welcome, not a model reply. The deployment therefore had no working
conversational provider (or the provider failed and fell back).

Vercel cannot reach a loopback gateway running on this PC. Production requires:

```text
FREELLMAPI_BASE_URL=https://<public-https-gateway>/v1
FREELLMAPI_API_KEY=<server-side secret>
FREELLMAPI_MODEL=auto:reliable
ECHO_SESSION_SECRET=<long random value>
SESSION_SECRET=<long random value>
```

Set these in Vercel Project Settings -> Environment Variables and redeploy.
Never use a `VITE_*` variable or frontend code for any of them. After deploy,
verify `/api/echo/provider` reports `configured: true` and `reachable: true`, and
that a model-only prompt returns provider metadata. If the gateway is only on
the PC, an HTTPS tunnel is required; no tunnel is configured by this repository.

## Residual risks

- History and revocation are process-local; serverless instances do not share
  them, so remote context may reset between requests.
- The portal's `server/utils/auth.ts` still has a public default cookie secret
  when `SESSION_SECRET` is unset. This is pre-existing and must be set privately
  in production; it is the outer authentication gate for ECHO.
- Portal-wide reflected CORS remains; ECHO origin checks are an additional gate,
  not a replacement.
- Stop aborts the browser request and discards the token but cannot guarantee
  upstream cancellation or billing behavior.
- No private school records are supplied to the model; only typed text, page
  route and short in-memory history are sent.
